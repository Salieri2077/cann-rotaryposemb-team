## 1. 当前是怎样的组合

当前版本是历轮保留方案的累积，加上本轮胜出的 positions 单缓存直接同步。它是目前选定、通过完整验证的基线，**没有证明是所有方法的最优组合，更没有穷举全局最优**。历史优化多为逐步试验，不是每个因素都有独立消融。

| 已保留组成 | 作用与代码依据 |
| --- | --- |
| 联合 sin/cos、共享中间量、精确 Axpy 范围约简 | `FinishTrig`，kernel.asc:539；theta<1 保留完整标量 Payne–Hanek |
| 跨 token 合并系数计算，跨 head 复用系数 | `Process` / `MultiplyTrig` / `ExpandTokenTrig`；低 H 批量、高 H 共享两种策略 |
| x/y 各两块缓冲，共享路径提前搬下一 head 块及同系数窗口下一 token | `Init`，386–387；`ProcessSharedToken`，960–985 |
| 对齐行连续 DMA、适用维度的整行向量旋转 | `CopyIn` / `CopyOut` / `ComputeWholeRows`；非对齐输入保留填充布局 |
| 小张量独立入口、常见 D 的紧凑参数、宽 D 的无损频率编码 | `OneTokenKernel`，1066；`run_kernel`，1296、1371 以后 |
| positions 256B 单缓存，MTE2↔Scalar 显式同步 | `Position`，503；这是最新一轮实际加入的改动 |

本轮未保留：额外的 positions 双缓存预取、单缓存额外空间对照、角度缓冲 bank 错位、π/2 多项式改写、Payne–Hanek 乘积窗口缩减。前三类中，positions 双缓存和单缓存是替代关系；原有 x/y 双缓冲始终保留。数学函数的替代实现也不能简单同时启用。

bank 错位与 positions 单缓存可以组合，但组合只有本地验证，没有正式 NPU 结果。扩大普通约简范围到 196608 也只有本地验证。不能把这些候选直接放入生产内核并称作“强强联合”。原始数据和独立补丁见[本轮实验](README.md)。

## 3. 源码暴露出的具体疑点

### B1：低 head 路径的 position 等待可能被 x 搬运拖住

`ProcessTokenBatch`（1031–1036）先 `CopyIn(x)`，随后在逐 token 循环中调用 `Position`。如果 position 缓存未命中，其搬运和 `MTE2_S` 事件排在此前 x 搬运之后，可能使 Scalar 必须先等较大的 x 搬运，才能开始生成与 x 内容无关的三角系数。共享路径（486–487）已经先取第一个 position，再发 x 搬运。

**最小实验 E1：** 低 head 路径仅提前读取首个真实 position，复用该值，再发 x 的 CopyIn；其余计算、tile、缓存大小和事件保持不变。针对每次首批缓存 miss、64 项边界、较长 batch 的中途 miss，以及命中情形分别测试。如果大部分等待发生在中途 miss，首项调整可能不足，届时再考虑整段 position 的发起顺序。

验证信号：位置读取前后的 Scalar 等待缩短、x 搬运与 trig 计算重叠增多，且完整内核复测改善。不保证首项提前一定更快；提前执行的等待也可能推迟 x 搬运。

### B2：共享路径只预取窗口内部，没有跨工作单元接上首块

`ProcessSharedToken` 已提前搬下一 head tile，或同一系数窗口的下一 token；`Process` 用 `t + 1 < tokenCount` 控制预取。窗口/工作单元末尾没有请求下一单元的第一块，下一轮重新执行 position、首块 x 搬运及系数计算（459–499）。当每核连续处理多个较短单元时，这可能造成反复的启动等待。

**最小实验 E2：** 首先只覆盖 groups==1 且每核至少两个工作单元的共享路径，明确计算下一单元的 firstRow/firstRows，在当前末块计算前排入其 x 搬运；下一单元跳过重复 CopyIn。必须区分“下一 token”和“同一 token 的另一 head group”，遵守本核 begin/end，保证两块输入缓冲的所有权；优先复用已有双缓冲，不新增整份角度区。

验证信号：工作单元边界的 Vector 空隙减少；单单元、跨 head group 和尾部输入不回退。不把低 H 的普通 CopyIn/Compute/CopyOut 循环称为硬件全串行：队列本身是异步的，即使没有手写 lookahead，也可能发生重叠。旧提交 230620 已尝试低 H 跨 batch x 预取但未胜出，E2 是不同边界，应独立验证。

### B3：theta<1 的范围约简选择过粗，但是否影响评测未知

`run_kernel`（1300、1311）只根据 theta<1 设置 wideAngles；`FinishTrig`（548–556）随后对整个 `count` 做 Scalar GetValue → Payne–Hanek → SetValue，包括 RowStride 的填充位置。即使部分真实角度处于普通约简的安全域，也进入该循环。

**最小实验 E3a：** 每 token 只对前 HalfDim 个真实角度做标量 PH，保留填充槽原值。频率填充区初始化为 0（401–403），公开合法 position 为有限整数，因此它们的角度为 0。FP16 D16 的 RowStride=16、HalfDim=8，可省该标量循环一半的元素；FP32 D18 为 9/16 有效，可省 43.75%。这些比例只描述该循环，绝不等于整体内核加速；对齐 D 或普通角度分支可能完全无收益。仍需保证所有真实维度都处理，特别是真实频率 Inf 与 position=0 产生的 NaN 不能当作 padding 跳过。

**后续候选 E3b：** 用每次调用已生成的真实 FP32 频率和公开 position 上界证明安全范围；全域安全时选向量约简，混合情况尝试按对齐频率段处理。非有限角度、超出安全域和边界必须保留完整处理。使用当前 131072 安全域时，theta<1 且按最大 position 估界往往只有首个频率可用快速路径，收益可能很小；使用 196608 扩展域也必须先完成对应完整输出和 NPU 验证。

历史边界：230707 的运行时有界角度检测已上线通过但未胜出；本轮 host 上界 196608 的候选仅本地验证。E3b 应说明相对旧方案减少了哪一段检测或标量工作，不能只改名字重试。theta<1 时逆频率通常随 i 增大，因此可用普通约简的部分通常是低 i 的前缀；不能直接套 theta>1 的“低频尾部”说法。

### B4：分块在系数复用、指令数量和并行度之间仍有取舍

低 H 批量策略使用 H<=4 条件（1328），其他情况共享系数；共享路径仍逐 token 调用旋转（495–498），即使几个 token 的 trig 已一起算完。宽 D 的频率解码在每核初始化执行（412–456），并有严格参数容量限制。

**候选 E4：** 对 H=3/4/5/8 邻域试小型 token×head 二维块，使 x 搬运与旋转指令都能合并，同时测系数广播增加的 UB 流量；只合并 DMA 不足以证明有效。若 profile 显示初始化/标量发射为主，再研究更合适的 tokenGrain、每核任务数或宽 D 解码布局，避免先改动全部参数。

成本提示：旋转主体每对元素 4 乘 2 加，共约 3NHD FLOPs，读 x 写 y 至少 2NHD×sizeof(dtype) 字节，N=B×S。仅旋转的算术强度为 FP32 0.375、FP16 0.75 FLOP/B。trig 理想复用成本随 ND 而旋转/搬运随 NHD 增长；head 分组跨核会额外重复系数计算。该模型用于划分实验输入，不能代替真实带宽测量。

宽 D 初始化应另行归因：`InitFrequencies`（414–453）每核逐项写频率，编码路径每三个频率串行做整数预测与残差修正；host（1376）还对 raw 路径无条件计算一次实际未使用的 ratio powf。后者可作为低成本清理候选，但只会减少一个主机 powf 调用，平台计时是否覆盖它尚未核实。只有确认编码初始化占比后，才值得尝试向量解码；必须逐位保留预测舍入与整数残差，不能直接改为普通几何递推。

## 4. 还值得保留的数学与组合方向

- **theta==1 的精确特化：** 所有频率为 1，每 token 只需一对 sin/cos，复用于 D/2 个维度。应保留当前角度的 FP32 语义，计入广播代价；不知道隐藏测试是否覆盖这一条件。
- **重复 position 的调用内复用：** 必须读取实际输入并确认相同 position，只对足够长的重复区间考虑复用。任意 position 的一般路径仍需正常计算，不能假设连续或按测试编号选择。
- **普通角度的低频段短多项式：** 基于实际窗口 max(position) 和实际频率建立保守界，只在有足够长的安全片段时省去范围约简。阈值计算、分段和广播都有成本；默认 theta 不保证存在这种片段。
- **当前 P + bank 布局的四组对照 E5：** 在同一时段比较 B、P、U、P+U，其中 B 为前版，P 为位置同步，U 为 bank 调整。两种单项收益不能相加；资源地址和调度改变后可能互相影响。组合源码尚无 NPU 结果，本轮不纳入。

连续 position 的三角递推不是优先方向：题目没有连续性保证，而且参考逐次计算 FP32(position×frequency)，递推会改变舍入并累积误差。减少多项式阶数也不必然降低完整内核耗时，本轮 π/2 实验已经给出反例。

## 5. 下一轮顺序与验收

1. **先做 E1 的小改动**，保持当前内核为原样对照；补缓存 miss/hit 和边界覆盖，再看完整 NPU 输出与耗时。
2. **建立可定位的性能测量。** 有匹配 NPU/工具链时，选已知 shape 的小/大 H、窄/宽 D、对齐/非对齐、普通/宽角度输入，记录 pipe 利用率、内存带宽及 bank 冲突；隐藏第 10 点无法直接复现时，只说覆盖了公开构造的参数族，不声称定位了该点。
3. 根据轨迹选择 E2（边界等待）、E3a/E3b（宽角标量工作）或 E4（指令/布局成本）。E5 可用少量组合实验检查已完成工作的交互，不默认有收益。
4. 以本记录固定的 P 源码为下一轮基准，每次只改一个因素。先做交替 A/B/A 初筛；候选进入保留阶段时尽量收集至少 5 组成对测量或 ABBA 块，记录分布及异常，不只取最小值。多次提交仍未必完全消除平台漂移。
5. 每次保存源码 SHA、公开测试参数、原始时间、逐点比例、几何平均、耗时总和及正确性；有 profile 时关联其文件。完整算子输出全部通过才能替换基线。

独立的“仅搬运”“仅角度生成”“带已生成系数的旋转”microbenchmark 只用于本地定位。它们改变了资源竞争和重叠关系，不能简单从总时间相减来精确归因，也不能作为符合完整题意的正式性能结果。现有本地 runner 的 host_launch_batch_average_us 含主机分块、启动和同步，平台 time 的聚合与 host/device 边界尚未核实，应分别记录。

官方[DoubleBuffer 说明](https://asc.gitcode.com/guide/operator_practice/simd_operator_optimization/pipeline_scheduling/enable_double_buffer.html)支持 MTE 与 Vector 的流水重叠，也指出短任务或搬运占比小的情况下可能没有收益。官方[性能调优指南](https://asc.gitcode.com/guide/programming_guide/debug_and_tuning/performance_tuning.html)列出 msOpProf 上板/仿真方式及 PipeUtilization、Memory、ResourceConflictRatio 等指标。当前环境没有采集这些硬件指标；应以匹配 CANN 9.0.0 / dav-2201 的工具能力为准。
